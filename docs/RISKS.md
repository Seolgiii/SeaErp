## 0. /api/inbound-receive에 멱등 가드가 없다 (⚠ 런칭 전 필수)

- **증상**: `lib/inbound-airtable.ts:33-42`가 `currentStock + receivedQty`를 그대로 PATCH한다.
  같은 요청이 두 번 들어오면 **재고가 두 번 더해진다.** 모바일 작업자 경로라
  더블탭·네트워크 재시도가 실제로 일어난다.
  `X-Idempotency-Key`도, 도메인 수준 가드(승인상태 재확인 같은)도 없다 —
  재고를 움직이는 POST 중 유일하게 어느 쪽 보호도 없는 경로다.
- **위치**: `app/api/inbound-receive/route.ts` → `lib/inbound-airtable.ts:24-53` `receiveInbound()`
- **조치**: `X-Idempotency-Key` 적용 또는 도메인 수준 가드. 구현은 별도 작업.
- **발견일**: 2026-08-05

## 1. 품목마스터에 원물 '갈치'가 없다

- **증상**: 갈치 계열은 `선동갈치 CT1`·`선동알치 CT2`·`육동알치 CT3`·`갈치살 CTF`가 있는데
  원물 '갈치'만 없다. 품목코드를 정할 수 없어 갈치 입고분은 LOT번호를 만들지 못한다.
- **위치**: Airtable `품목마스터`
- **발견일**: 2026-04 최초 기록, 2026-08-04 재확인

## 2. 통(桶) 구분이 없어 원프로즌이 베이트小로 잘못 들어간다

- **증상**: 원프로즌은 통에 담아 운반하는데 생산내역 '구분'에 통이 없다. 지금은 베이트小로
  기록된다. 통 수량을 통 개수로 셀지 박스 환산으로 셀지도 미결이고, 이 값이 작업단가의
  분모라 전 품목 원가에 영향을 준다.
- **위치**: `lib/work-settlement-rates.ts:26` — `BoxType = "사료팬" | "베이트大" | "베이트小"`
- **발견일**: 2026-07-16

## 3. 동결비를 단일 컬럼으로 읽어 값이 null로 빠질 수 있다

- **증상**: 라이브 `보관처 비용 이력`의 동결비는 팬/베이트大/베이트小 3열로 나뉘어 있는데,
  보관처 비용 조회는 옛 단일 `동결비` 컬럼을 읽는다. 해당 보관처는 동결비가 null로 빠진다.
- **위치**: `lib/storage-cost.ts:83`·`:115` (단일 `SC.freezeFee` 참조).
  3열 매핑은 `lib/work-settlement-rates.ts:65-67`에 이미 있다.
- **발견일**: 2026-07-14

- **위치**: `app/actions/inventory/inbound.ts:179` /

## 6. LOT번호 형식이 규격 결측을 안전하게 표현하지 못한다

- **증상**: 규격이 비면 하이픈이 3연속으로 붙는다(`260804-MC1---26-0001`). 구분자와 값을

  근거가 없다.
- **조치**: `buildLotNumber` 3곳 통합 작업(4번)과 함께 형식 규칙을 재설계한다.
  **단독 수정 금지.**
- **위치**: `app/actions/inventory/inbound.ts:179` 외 2곳(4번과 동일)
- **발견일**: 2026-08-04

## 15. 지출결의 카테고리 Automation 3종이 조건 중복으로 비결정적 동작

- **증상**: 카테고리에 이름이 빈 선택지(`selVZeMSn2jiuxYKy`)가 있고, Automation 3종이
  전부 `isEmpty({카테고리})`를 조건으로 건다. 카테고리가 비면 셋 다 발동하고
  마지막 실행분이 이긴다.
- **위치**: Automation `wfleXsCYrE2uWadWq`(식대) · `wflNLd16fgBWBAB88`(유류비) ·
  `wflAa6SqDUphY3Pyg`(소모품비). 전부 deployed. 상세는 `docs/airtable-logic.md` §2-1~2-3, §3-4~3-5
- **실측(2026-08-05)**: 빈 이름 선택지를 쓰는 레코드 **0건**. 지출결의 테이블 자체가
  **전체 1건**(카테고리=유류비)이라 지금까지 이 충돌이 실제로 터질 일이 없었다.
  지출 등록이 늘기 시작하면 바로 드러난다.
- **조치**: Automation 재설계 + 빈 선택지 정리. 별도 작업.
  빈 선택지는 **아직 제거되지 않았다**(2026-08-05) — Airtable API/MCP로는 singleSelect
  선택지를 편집할 수 없어 UI에서 직접 지워야 한다. 지워도 `isEmpty({카테고리})` 조건
  중복 구조는 그대로 남으므로 이 항목은 닫히지 않는다.
- **발견일**: 2026-08-05
