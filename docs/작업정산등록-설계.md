## 0. 한 줄 요약

**작업 정산 등록** = 수협 정산서를 그대로 옮겨 적는 관리자 PC 폼. **① 생산내역**(사이즈별 매입·원가 = 매입 통계의 원천) + **② 작업비**(수수료·노임·동결비 등 경비 풀) 2블록. 확정하면 **생산내역 1줄 → 입고관리 1행 + LOT 1개**가 자동 생성된다(가공 완료 패턴 재사용). **LOT은 동결·선별 후 여기서 생성**, 원물 매입은 여기서 기록된다("매입 기록 ≠ LOT"은 **입고관리=매입기록 / LOT=재고단위**로 자연 분리).

## 1. 범위 (v1 vs 차후)

**v1 (이번 구현 대상)**
- 3개 신설 테이블(헤더·생산내역·작업비) + 관리자 PC 워크리스트 화면.
- 확정 시 입고관리+LOT 자동 생성 + 원가(작업단가·실단가) 롤업.
- 작업비 단가 기본값 = **코드 하드코딩 rate 테이블**(v17 확정 기본값). 동결비·입출고비만 기존 `보관처 비용 이력`에서 자동.
- 매입 통계는 **입고관리를 계속 읽되**(§6), 원물 원천이 작업 정산으로 바뀜 + 용도 태그 세그먼트.

**차후 (스코프 아웃 — 별도 작업)**
- 정산서 **대외 발송용 100% 재현**(여노임·협회부담·지급처별 서식). 지금은 내부 매입·원가용 핵심만.
- **작업 경비 단가 마스터**(관리자 인라인 수정) — v1은 하드코딩, 이후 `가공비 단가` 패턴으로 테이블화.
- **공동배분**(한라/태봉/대경/J.P 등 다자 배분) — §9-Q3.
- 수율(투입 원물 총량 vs 산출) 필드 — 원물 동결은 수율 개념이 약함(선별 손실 위주). ONE/TWO-Frozen 가공은 기존 `가공 거래`가 담당.
- 제품 동결·ONE-Frozen 경로 통합(지금은 **원물 동결 경로**만 — 유일하게 정산서가 있는 성숙 경로).

## 2. 핵심 아키텍처 결정 ✓

### 2-A. 생산내역 1줄 → 입고관리 1행 + LOT 1개 ✓
라이브 스키마 확인 결과 **모든 LOT은 입고관리 짝이 필수**다(출고가 `입고관리.잔여수량`을 차감하므로). 가공 완료 코드(`completeProcessingBatch`)가 이미 "입고관리 행 + LOT 동시 생성" 패턴을 쓴다 → **그대로 차용**.

```
작업 정산 (헤더)
 ├─ 생산내역 line A (갈치 · 사료팬 · 규격10 · 26미 · 30박스 · 수매단가 X)
 │     └─(확정)─▶ 입고관리 행 A(수매가=수매단가) + LOT A(수매가=실단가)
 ├─ 생산내역 line B ...
 └─ 작업비 (수수료·노임·동결비·…) ── 합산 ─▶ 작업단가(원/박스) ─▶ 각 line 실단가
```

### 2-B. "매입 기록 ≠ LOT"의 물리적 구현 ✓
- **입고관리.수매가 = 수매단가**(순수 원물 매입가, 박스당). → 매입 통계·손익 현금흐름의 매입액.
- **LOT.수매가 = 실단가 = 수매단가 + 작업단가**(박스당 재고원가). → 재고원가·판매원가의 바닥.
- 즉 같은 사건이 입고관리엔 "매입", LOT엔 "재고원가"로 서로 다른 값으로 남는다 — 논쟁의 해소가 데이터 레벨에서 자연히 이뤄짐.

### 2-C. 경비 이중계상 방지 ✓ (가공 완료와 동일 철학)
작업비(동결비·입출고비 등 1회성 경비)는 **작업단가에 이미 흡수** → LOT엔 다시 부과하지 않는다.
- **작업 정산 LOT**: `동결비=0`, `입출고비=0`, `노조비=0`, `이월비용 4종=0`. **냉장료단가만** 행선지 보관처의 `보관처 비용 이력`에서 읽어 저장(냉장료는 1회성 작업비가 아니라 보관일수 누적분 → 최초입고일부터 앞으로 적산, 이중계상 아님).
- 근거: 가공품 LOT도 `이월비용=0`·동결비 미부과로 보관비 이중계상을 막는다(`master-processing.ts` 확인). 작업 정산 LOT도 동일 규칙.
- ⚠ 주의: 이 규칙을 어기면 `LOT.판매원가` formula(수매가+누적냉장료+입출고비+노조비+동결비)가 동결비·입출고비를 **두 번** 계산한다. → §10 사각지대 1순위.

## 4. 원가 배선 (핵심 로직)

### 4-A. 작업단가 → 실단가 → LOT.수매가
```
작업비총액         = Σ 작업비.금액   (v1: 전부 원가 포함 — Q1 확정)
총박스수           = Σ 생산내역.수량(박스)
작업단가(원/박스)  = 작업비총액 ÷ 총박스수                 ← 정산 1건당 산출(고정 아님)
실단가(line)       = 수매단가(line) + 작업단가            ← 전 라인 동일 작업단가 가산(균등 배부)
LOT.수매가         = 실단가                                (박스당 재고원가)
입고관리.수매가    = 수매단가                              (순수 매입가)
```
- **균등 배부(÷총박스수)** = v17·메모리 확정. 사이즈별 무게 가중은 차후 검토(지금 안 함).
- 순수함수로 추출 → 단위 테스트(가공 `calculateProcessingCost` 패턴). 파일 `lib/cost-calc.ts`에 `calculateWorkSettlementCost` 추가.

### 4-B. 동결비·입출고비 = 보관처 비용 이력에서 자동 ✓
v17 "지급처=보관처 선택 시 단가 자동"의 실체 = **기존 `보관처 비용 이력`**. 라이브 확인:
- `동결비 (팬)` / `동결비 (베이트大)` / `동결비 (베이트小)` + `입출고비` + `냉장료` + `노조비` + 적용기간.
- 작업비 입력 시 지급처(보관처) 선택 → 해당 보관처·작업일의 이력 행에서 단가를 읽어 채운다(가공비 단가 `findApplicableRate` 패턴).

### 4-C. 구분(박스종류) → 작업비 수량·단가 자동연동 ✓
`동결비 (팬/베이트大/베이트小)` 3열이 생산내역 `구분` 3옵션과 1:1 대응 (`lib/work-settlement-rates.ts:FREEZE_FEE_COLUMN` 상수·테스트):
| 생산내역 구분 | 동결비 열(보관처 비용 이력) | 박스비(하드코딩) | 탈펜료(하드코딩) |
|---|---|---|---|
| 사료팬 | 동결비 (팬) | 펜사용료 350 | 350 |
| 베이트大 | 동결비 (베이트大) | 박스(大) 1,100 | 350 |
| 베이트小 | 동결비 (베이트小) | 박스(小) 900 | 200 |
→ **박스비·탈펜료**는 박스종류별 단가가 코드 하드코딩(재료비, 보관처 무관) — ✅ 이미 반영(Phase 2). **동결비**는 보관처마다 단가가 달라 하드코딩 X, 지급처 보관처의 해당 열에서 읽음 — **회수 = 구분별 박스수 / 단가 = 보관처 비용 이력 열 → 박스종류별로 각각 라인 생성**(Phase 3 서버 액션). 즉 베이트大 라인 → 동결비(베이트大) 단가 × 베이트大 박스수.

## 6. 매입 통계 원천 재배선 (§ Task 2)

**결론: Strategy A — 입고관리를 계속 원천으로 둔다.** 재작성 최소.

- 작업 정산이 만든 입고관리 행은 `수매가=수매단가(순수 매입)`이라 **기존 `getPurchaseStats`가 그대로 정확**하게 집계한다(품목·규격·미수·매입처·선박 차원 이미 지원).
- **재배선 실체 = 원물 매입의 "입구"가 모바일 입고 → 작업 정산으로 이동**한 것. 스키마·집계식은 불변, 데이터 출처만 바뀜.
- **추가 1: 용도(처리구분) 세그먼트** — 입고관리.비고에 용도 태그를 실어 통계에서 원물동결/원프로즌/생물 필터. (`PurchaseProductDay`에 `usage` 차원 추가 — 소규모.)
- **추가 2: 제외 규칙 보강** — 현재 `기존 재고`·`재고 이동` 제외. `가공 입고`(수매가=0)도 명시 제외 권장(현재는 0이라 금액엔 무해하나 건수·priceMissing 오염). 작업 정산 태그는 **실매입이므로 포함**.
- **전환기 주의(사각지대)**: 같은 원물을 (구)모바일 입고 + (신)작업 정산에 **이중 입력하면 매입 2배 집계**. → 운영 안내로 원물 입구를 작업 정산으로 단일화(모바일 입고는 완제품/물품 입고 전용). 구 데이터는 그대로 둠(최소 수정).

## 10. 검증 사각지대 (비개발자 두 번째 눈)

1. **경비 이중계상(1순위)** — 작업비에 넣은 동결비·입출고비를 LOT에도 `보관처 비용 이력`으로 부과하면 판매원가가 2배. §2-C 규칙(작업 정산 LOT은 냉장료만) 준수 필수. 통합 테스트로 LOT.판매원가 == 실단가+냉장료 검증.
2. **매입 이중집계** — 구 모바일 입고와 작업 정산 동시 입력 시 매입 2배(§6). 자동 방어 없음 → 운영 규칙 의존. 사각지대.
3. **작업단가 균등배부의 왜곡** — 무게 다른 사이즈에 박스당 균등 가산 → 저가 소형 사이즈의 실단가가 상대적으로 과대. 확정 설계지만 원가 정밀도 한계로 명시.
4. **UI 전량 도그푸딩** — 워크리스트 자동연동(구분→회수, 종료−시작→시간, 지급처→단가)은 손 검증만. 테스트는 원가 순수함수·확정 생성에 집중.
> Q2=확정 때만 LOT 생성으로 '임시저장 LOT 잠정원가' 사각지대는 원천 제거됨.
