# SEAERP DESIGN.md

**v0.4.4** · 최종 개정 2026-08-04

> UI 작업 시 이 문서를 항상 참조한다.
> 여기 정의된 토큰은 **고정값**이며, 개별 화면 요청에서 임의로 변경하지 않는다.
> 레퍼런스는 **레이아웃·인터랙션 패턴만** 차용하며, 색·폰트·간격은 항상 이 문서를 따른다.

---

## 0. 이 문서의 적용 방식

이 문서는 코드보다 나중에 쓰였다. 기존 33개 화면은 대부분 이 규칙 이전에 만들어졌으므로, **전면 일괄 적용을 목표로 하지 않는다.**

- **신규 화면·신규 컴포넌트** → 이 문서를 처음부터 지킨다. 예외 없음.
- **기존 화면** → 그 화면을 다른 이유로 수정할 때 함께 정리한다. 규칙 준수만을 목적으로 한 대규모 치환은 하지 않는다.
- **토큰 시범·확산 작업** → 규칙 준수 자체를 목적으로 하는 작업. 위 두 번째 항목의 예외이며, 시범으로 검증된 토큰·컴포넌트를 계획적으로 확산하는 경우에 한한다.
- **예외**: 접근성 미달(대비 4.5:1 미만), 상태 오표시, 기능 결함으로 이어지는 불일치는 발견 즉시 고친다.
규칙을 지킬 수 없는 상황이면 규칙을 어기지 말고 **이 문서를 고친다.** 지켜지지 않는 규칙이 쌓이면 문서 전체가 무시된다.

## 1. 두 개의 표면

SEAERP은 하나의 제품이지만 **성격이 다른 두 표면**으로 구성된다. 규칙은 표면별로 다르게 적용된다.

| | 모바일 PWA | 관리자 (/admin) |
|---|---|---|
| 경로 | `/`, `/inventory/*`, `/expense/*`, `/my-requests` | `/admin/*` |
| 사용자 | 현장 작업자 | 관리자 |
| 상황 | 입고장에서 장갑 끼고 한 손으로 | 책상에서 모니터로 |
| 우선순위 | 오조작 방지, 큰 터치 타겟, 최소 정보 | 정보 밀도, 스캔 속도, 최소 클릭 |
| 레이아웃 | 반응형 (카드 리스트) | **데스크톱 전용** (테이블) |
| 최소 지원 폭 | 375px | 1280px |
| 그 이하에서 | 세로 스택 | 축소하지 않고 가로 스크롤 |

**`/admin`에 모바일 레이아웃을 만들지 않는다.** 관리자 화면을 휴대폰에서 여는 것은 지원 대상이 아니다.

**표면 판정은 입력 장치 기준(`any-pointer: fine`)으로 한다.** 창 폭(`min-width`)으로 판정하면 노트북에서 창을 좁혔을 때 모바일로 오판한다.

공통 원칙: 이것은 **내부 운영 도구**다. 마케팅 사이트가 아니다. 장식적 요소(그라데이션, 이모지, 불필요한 아이콘, 애니메이션)는 넣지 않는다.

## 2. 토큰

### 2-1. 토큰 구현 규칙 (가장 중요)

- **모든 토큰은 `tailwind.config.ts`의 `theme.extend`에 단일 정의한다.** 화면 파일에 hex 리터럴, `text-[Npx]`, 임의 radius를 쓰지 않는다.
- **Tailwind 기본 팔레트(`gray-*`, `slate-*`, `red-*` …)를 그대로 쓰지 않는다.** 특히 `gray`와 `slate` 두 계열 혼용 금지.
- **값이 아니라 역할로 이름 짓는다.** `rounded-[16px]`가 아니라 `rounded-card`. 코드는 "이것이 카드다"만 말하고, 얼마나 둥근지는 토큰이 결정한다.
- 색 하나에 hover/active 값을 함께 정의한다. hover 색을 화면에서 즉흥 지정하지 않는다.

### 2-2. 중립색

| 토큰 | Light | 용도 |
|---|---|---|
| `--bg` | `#FBFBFC` | 페이지 배경 |
| `--surface` | `#FFFFFF` | 카드·테이블·패널 배경 |
| `--surface-alt` | `#F4F5F7` | 테이블 헤더, zebra row, 비활성 영역 |
| `--border` | `#E3E5E9` | 구분선, 카드 테두리 |
| `--text` | `#14171C` | 본문 |
| `--text-muted` | `#646B78` | 보조 라벨, 캡션 (흰 배경 대비 5.35) |
| `--text-faint` | `#98A0AC` | **placeholder·비활성 전용** (대비 2.61) |
| `--link` | `#1C6CE0` | 클릭 가능한 텍스트 (표 행 제목 등) |
| `--scrim` | `rgba(0,0,0,.45)` | 모달·시트 뒷배경. 순수 검정을 직접 쓰지 않는다 |

`--text-faint`는 대비 미달이므로 **정보를 담은 텍스트에 쓰지 않는다.** 빈 상태 문구, 값 없음 표시는 `--text-muted`를 쓴다.
`--text-faint`는 비활성 아이콘에는 쓸 수 있다. 정보를 담지 않는 비활성 상태에 한하며, 값이나 라벨을 나타내는 아이콘에는 쓰지 않는다.

중립색은 살짝 차가운 회색(cool gray) 계열로 고정한다.

### 2-3. 액센트 — 면과 글자를 분리한다

파스텔은 **면(배경·뱃지)에만** 쓰고, **글자·아이콘·테두리에는 같은 계열의 진한 값**을 쓴다. 이 분리를 지키지 않으면 파스텔 배경 위 파스텔 글씨가 되어 현장 조명에서 읽히지 않는다.

**채움 버튼(solid)의 배경은 파스텔이 아니라 별도의 진한 값을 쓴다.** 흰 글자가 얹히기 때문이다.

| 의미 | 면 (`--*-bg`) | 글자·테두리 (`--*-ink`) | 대비 | 채움 배경 (`--*-fill`) |
|---|---|---|---|---|
| Primary | `#DCEAF5` | `#235C82` | 5.78 | `#1C6CE0` (흰 글자 4.92) / hover `#1A61CC` (5.79) |
| Success | `#DDEFE4` | `#1F6644` | 5.76 | — |
| Warning | `#F7EBD6` | `#7A5510` | 5.68 | — |
| Danger | `#F7DFE0` | `#8A2A35` | 6.74 | `#C0392B` |
| Info | `#E4E2F5` | `#453E85` | 7.25 | — |

> v0.2까지 쓰던 `#2C6E9B` / `#2F7D55` / `#96702A`는 실측 대비가 4.5:1에 미달하거나 경계선이었다. 위 값으로 대체한다.
> Primary 채움 배경으로 `#3182F6`을 쓰지 않는다 — 흰 글자 대비 3.71로 미달이다.

**사용 규칙**
- 한 화면에 액센트 컬러는 **최대 2종**. 표 행 액션 버튼은 이 계산에서 제외한다.
- Primary 채움 버튼은 **화면당 1개**. 표의 행 액션, 빈 상태 안내 버튼은 Secondary 또는 Ghost로 한다.
- 색만으로 상태를 표현하지 않는다. → 자세한 규칙은 §6-2 참조.
- 브랜드 컬러는 넣지 않는다. 필요해지면 `--accent-fill` 한 줄만 교체한다.
- **오버레이(모달·바텀시트)는 독립 표면으로 센다.** 페이지에 Primary 1개, 모달에 Primary 1개는 위반이 아니다.
- **"최대 2종"은 상태 배지에 적용된다. 분류 배지는 예외다.** 분류 가짓수는 도메인이 정하므로 줄일 수 없다.
  단 의미 있는 값에만 색을 주고 나머지는 중립으로 둔다. (예: 자사창고만 액센트, 나머지 중립)
- hover/active 값은 토큰에 함께 정의한다. 화면에서 즉흥 지정하지 않는다.

### 2-4. 대비 기준

- 본문·배지 텍스트 **4.5:1 이상**, 큰 텍스트·아이콘 **3:1 이상**.
- 배지 글자는 11~12px이므로 "큰 텍스트" 예외에 해당하지 않는다. 4.5:1을 적용한다.
- **이 기준은 색상 취향보다 우선한다.** 파스텔이 예뻐도 대비를 못 맞추면 진한 값을 쓴다.

### 2-5. Radius — 역할로 정의하고 값은 표면이 결정한다

```
--r-control   버튼, 입력, 셀렉트
--r-card      카드, 패널
--r-sheet     바텀시트, 모달
--r-pill      배지 (999px, 표면 무관 고정)
```

| 토큰 | /admin | 모바일 PWA |
|---|---|---|
| `--r-control` | 6px | 12px |
| `--r-card` | 12px | 16px |
| `--r-sheet` | 16px | 24px |
| `--r-pill` | 999px | 999px |

코드에는 `rounded-card`라고만 쓴다. 나중에 톤을 조정하고 싶으면 **CSS 변수 한 줄**만 고친다. 화면 코드는 건드리지 않는다.

> 2026-07-28: /admin의 `--r-card` 10 → 12, `--r-sheet` 12 → 16으로 올렸다.
> 실제 화면(보관처 마스터)에 적용해 보니 10/12는 각지게 읽혀 카드 경계가 딱딱했다.
> 값 정의는 `app/globals.css`의 `[data-surface='admin']` 한 곳뿐이라 화면 코드는 손대지 않았다.

### 2-6. 간격

- **8px 그리드.** 스케일: `4 / 8 / 12 / 16 / 24 / 32 / 48`
- **Tailwind `.5` 유틸(`py-2.5`, `gap-1.5` 등 = 2/6/10/14px)을 쓰지 않는다.**
- 카드 padding은 **16px(밀집) / 24px(일반) 2종**만 쓴다.
- **Shadow**: 거의 쓰지 않는다. 레이어 구분은 `--border`로 한다. 띄워야 하는 요소(드롭다운, 모달, 토스트)에만 `0 4px 16px rgba(0,0,0,.10)`.

## 3. 타이포그래피

| 역할 | 폰트 |
|---|---|
| 본문·UI 전체 | **Pretendard Variable** |
| 숫자 데이터 | `font-variant-numeric: tabular-nums` |

**전역 폰트는 반드시 하나다.** `globals.css`의 전역 선언과 화면별 `font-family` 선언이 달라서는 안 된다.

폰트를 교체할 때는 `font-variant-numeric: tabular-nums`가 실제로 동작하는지 반드시 확인한다.
tnum 글리프가 없는 폰트에서는 이 속성이 조용히 무시되어, 코드상 적용된 것처럼 보이지만
숫자 자릿수가 정렬되지 않는다. §7-5 전체가 무효가 되는 조건이다.

### 타입 스케일

| 토큰 | 크기 / 굵기 / 행간 | 용도 |
|---|---|---|
| `--t-page` | 20px / 600 / 1.3 | 페이지 제목 (h1) |
| `--t-section` | 16px / 600 / 1.4 | 섹션·카드 제목 (h2, h3) |
| `--t-body` | 14px / 400 / 1.5 | 본문, 테이블 셀 (PC) |
| `--t-body-mobile` | 15px / 400 / 1.5 | 모바일 본문 |
| `--t-input-mobile` | 16px / 400 / 1.5 | **모바일 입력 필드 전용** |
| `--t-label` | 12px / 500 / 1.4 | 폼 라벨 전용 |
| `--t-table-head` | 14px / 500 / 1.4 | 목록 표 헤더 전용 |
| `--t-caption` | 11px / 400 / 1.4 | 보조 설명, 배지, 오류 문구 |
| `--t-num-lg` | 24px / 600 / 1.2 | KPI 카드 수치 |

- **스케일 밖의 값을 쓰지 않는다.** 소수점 px(10.5 / 11.5 / 15.6px 등) 금지.
- 모바일 입력 필드가 본문보다 1px 큰 것은 **의도된 것이다.** iOS Safari는 16px 미만 입력에 포커스하면 화면을 확대한다. 본문과 맞추려고 15px로 되돌리지 말 것.
- **표 헤더(`--t-table-head`)와 폼 라벨(`--t-label`)은 크기가 다른 게 의도된 것이다.** 표 헤더는 같은 표의 셀(`--t-body` 14px)과 나란히 있어 12px이면 작아 보이지만, 폼 라벨은 입력칸 위에 단독으로 놓여 12px로 충분하다. 둘을 같은 토큰으로 묶지 말 것 — 표 헤더를 키우면 폼 라벨까지 따라 커진다.
- 제목에 별도 디스플레이 폰트를 쓰지 않는다. 단일 패밀리 + 굵기·크기 차이로 위계를 만든다.
- 텍스트는 문장형(sentence case). 전체 대문자·과한 자간 금지.

## 4. 반응형 (모바일 PWA 전용)

이 절은 **모바일 PWA에만 적용된다.** `/admin`은 §1의 데스크톱 전용 규칙을 따른다.

| | 모바일 (< 768px) | 태블릿 (768~1023px) |
|---|---|---|
| 목록 표현 | 카드 리스트 (테이블 가로스크롤 금지) | 2열 카드 그리드 |
| 노출 정보 | 핵심 3~4개 필드, 나머지는 상세 진입 | 동일 |
| 행 높이 | 최소 48px | 동일 |
| 터치 타겟 | **최소 44×44px** | 동일 |
| 폼 배치 | 1열 | 2열 허용 |
| 주요 액션 | 하단 고정 바 | 우측 상단 |

**입력 관련**
- 입력 필드는 `--t-input-mobile`(16px). 예외 없음.
- 터치 타겟 44px은 **padding이 아니라 `min-height`로 보장한다.** padding으로 만들면 폰트 크기가 바뀔 때 무너진다.
- 숫자 입력은 `type="text"` + `inputMode="numeric"`을 쓴다. **`type="number"`를 쓰지 않는다** — 스피너 화살표가 생기고 스크롤 중 값이 바뀐다.

## 5. 화면 유형별 레퍼런스

> 레이아웃·인터랙션 패턴 참고용이다. 색·폰트·간격은 위 토큰을 따른다.

- **리스트/테이블** (재고장, 입고 목록) → Linear (행 밀도, 키보드 조작), Notion DB 뷰 (필터·뷰 전환)

- **분석 대시보드** (원가, 재고 회전) → Metabase 계열 (KPI 카드 + 차트)

## 6. 컴포넌트

### 6-1. 공통 컴포넌트 강제

다음은 **공통 컴포넌트로만 만든다. 화면별 인라인 마크업·클래스 조합을 금지한다.**

| 컴포넌트 | 금지되는 것 |
|---|---|
| `<Button>` (Primary/Secondary/Ghost) | 화면에서 버튼 클래스 직접 조합 |
| `<StatusBadge>` | 화면별 `statusColor()` / `statusBadgeClass()` 정의 |
| `<EmptyState>` | `py-20 text-center` 인라인 |
| `<LoadingState>` | 인라인 `animate-spin` 블록 |
| `<ErrorState>` | — |
| `NumCell` / `NumHead` (`app/admin/_num-cell.tsx`) | 셀에 `text-right tabular-nums` 직접 조합 |

**버튼**
- 높이는 **PC 32px / 모바일 44px 고정.** padding으로 높이를 만들지 않는다.
- Primary는 화면당 1개. 표 행 액션·빈 상태 버튼은 Secondary 또는 Ghost.

### 6-2. 상태 배지

- **상태 → 색 매핑은 전역 단일 테이블로 관리한다.** 같은 상태는 어느 화면에서도 같은 색이어야 한다.
- 어휘와 매핑 고정:

| 상태 | 색 |
|---|---|
| 승인 대기 | `--warn` |
| 승인 완료 | `--ok` |
| 반려 | `--danger` |
| 취소 | 중립 |
| 소진 | 중립 |

> **반려(타인의 거부)와 취소(본인의 철회)는 다른 색군을 쓴다.** 둘 다 빨강으로 두면 구분이 안 된다.

- 배지 크기는 1종 고정: `--t-caption` + 좌우 8px + `--r-pill`.
- **점·아이콘만으로 상태를 표시하지 않는다.** `title` 툴팁은 대체 수단이 아니다 — 터치와 인쇄에서 사라진다.
- 배지는 상하 padding을 주지 않는다. `--t-caption`의 행간만으로 높이를 만들어,
표 행 높이(38px) 안에서 행을 밀어내지 않게 한다.

**정상이 대다수인 컬럼의 예외 규칙**

> 정상 상태가 대다수인 컬럼은 **정상을 조용히, 예외를 크게** 표시한다.
> 모든 상태에 동일한 무게의 배지를 다는 것은 이상 신호를 묻는다.

재고 조회의 상태 컬럼이 대표 사례다. 이 표는 인쇄해서 재고장으로 쓰이며, **정상이 아닌 LOT이 재고장에 들어가는 것 자체가 오류다.** 따라서 이 컬럼은 상태를 알리는 것이 아니라 오류를 잡아내는 장치다.

- 정상(활성) → 조용한 점. 텍스트 없음.
- 비정상 → 텍스트 배지 + `--danger` 계열. 흑백 인쇄에서도 읽혀야 한다.
- 가능하면 표 상단에 "비정상 N건" 요약을 둔다. 200행을 눈으로 훑지 않고 이상을 잡을 수 있어야 한다.

### 6-3. 폼과 입력

- 라벨은 `--t-label` 하나만 쓴다. **좌측 정렬 고정** (표 안 입력 그리드의 중앙 정렬만 예외).
- 필수는 라벨 옆 `*` + `--danger-ink`. **HTML `required`만 걸고 시각 표시를 생략하지 않는다.**
- **검증 오류는 해당 필드 바로 아래** `--t-caption` + `--danger-ink`로 표시한다.
  - 토스트는 필드에 귀속되지 않는 오류(저장 실패, 권한 없음)에만 쓴다.
  - **적용 범위는 입력 폼(등록·수정) 화면에 한한다.** 조회 화면은 제외.
- 오류 텍스트는 `--t-caption` 고정. 본문보다 크게 쓰지 않는다.
**PC 입력 필드 규격**
- 높이는 `--h-control`. padding으로 만들지 않는다.
- 배경 `--surface-alt` + 테두리 `--border`.
- 단, 카드 밖에 놓이는 입력(검색창 등)은 배경 `--surface`를 쓴다.
- 검색창 폭은 placeholder가 잘리지 않는 최소로 잡는다. 습관적으로 넓게 두지 않는다.
- 여러 줄 입력(textarea)은 `--h-control` 고정 높이의 예외다.
`rows`로 높이를 정하고 상하 padding 8px를 준다. 배경·테두리·radius는 단일 행 입력과 동일하다.

**오류 상태의 필드 스타일**
- 오류 발생 시 필드 테두리와 포커스 링을 `--danger-ink`로 바꾼다.
- 오류 메시지 표시(필드 아래)만으로 끝내지 않는다. 필드 자체가 상태를 나타내야 한다.
- 저장 실패 후 첫 오류 필드로 포커스를 되돌린다.

### 6-4. 빈 상태 · 로딩 · 오류

**빈 상태**
빈 상태는 두 종류이며 구조가 다르다. 컴포넌트에서 구분해 지원한다.

| 종류 | 조건 | 구성 |
|---|---|---|
| **등록 없음** | 데이터 자체가 없음 | 제목 + 다음 행동 + 액션 버튼 |
| **검색 결과 없음** | 필터·검색 결과가 0건 | 제목 + 조작 힌트 (버튼 없음) |

- 어느 쪽도 "…없습니다"로 끝내지 않는다.
- 액션 버튼은 Secondary 또는 Ghost로 한다. Primary는 화면 상단 1개로 유지한다.
- 문구 색은 `--text-muted`. `--text-faint`는 대비 미달이라 쓰지 않는다.

**로딩**
- 표/카드 골격을 유지한 **스켈레톤**을 쓴다.
- 전체 블록 스피너는 **최초 진입(레이아웃 미확정) 1회에만** 허용한다.
- 목록 표는 `_table-cols`의 `COLS`로 골격을 자동 생성할 수 있다(컬럼 수·폭을 이미 알고 있다). 공통 `<TableSkeleton cols={COLS} rows={8}>`로 대부분 커버된다.

**오류·토스트**
- 위치: PC 우측 하단 / 모바일 상단. 모바일은 하단 탭바와 겹치지 않게 오프셋을 둔다.
- `success`·`info`는 3초 자동 소멸. **`error`는 자동 소멸하지 않고 닫기 버튼을 둔다.**
- **서버 원문(`result.error`)을 그대로 노출하지 않는다.** 사용자 행동으로 번역하고, 원문은 콘솔·로그로 보낸다.

**파괴적 액션**
- 되돌리기 어려운 액션(삭제, 승인 취소, LOT 생성 확정)은 **디자인된 확인 시트만 쓴다. `window.confirm` 금지.**
- 확인 문구에 **대상명과 결과 개수**를 넣는다.

### 6-5. 모달

**구조**
모달은 헤더 / 본문 / 푸터 3영역으로 구성한다. 좌우 padding은 세 영역 모두 24px로 통일한다.

| 영역 | 상하 padding | 구분선 |
|---|---|---|
| 헤더 | 16px | 아래 `--border` 1px |
| 본문 | 24px | — |
| 푸터 | 16px | 위 `--border` 1px |

- 본문 내 필드 그룹 사이 간격 24px
- 라벨 ↔ 입력 8px, 입력 ↔ 도움말·오류 문구 8px
- 위 값은 모두 §2-6 간격 스케일(4/8/12/16/24/32/48) 안에 있어야 한다.
- 뒷배경은 `--scrim`

**푸터 버튼 배치**
- 파괴적 액션(삭제)은 좌측, 취소·저장은 우측
- 취소와 저장 사이 8px

**포털 주의**
앱 루트에 mount되는 오버레이(확인 시트, 토스트)는 `[data-surface]` 스코프 밖에 있다.
토큰을 쓰는 오버레이는 표면 정보를 포털에 함께 전달해야 한다.
그러지 않으면 `/admin`에서 열어도 모바일 값(radius 24px 등)을 받는다.

## 7. 목록 테이블 표준

### 7-1. 구조

- `overflow-x-auto` 래퍼 + `table-fixed` + `colgroup`
- **`minWidth`는 반드시 colgroup 합계에서 파생시킨다. 하드코딩 금지.**
  하드코딩하면 컬럼 추가 시 합계가 minWidth를 넘는 순간 브라우저가 전 컬럼을 비례 축소하며 **경고 없이 조용히 깨진다.**
- 컬럼 스펙(키·라벨·폭·정렬)은 공유 모듈(`app/admin/_table-cols.tsx`)에서 관리한다. 화면별 개별 선언 금지.
- **`thead`와 `tbody`는 같은 `<table>` 안에 둔다.** 헤더를 별도 테이블로 분리하면 가로 스크롤 시 어긋난다.

### 7-2. 넘침 처리

- **말줄임(truncate) 금지가 원칙이다.** 모든 값은 전부 보여야 한다.
- 폭이 부족하면 컬럼을 좁히는 게 아니라 **가로 스크롤**로 처리한다.
- 컬럼 폭 = 실측 데이터 최댓값 + 여유 8px + 셀 패딩
- **예외**: 자유 텍스트 컬럼(비고, 메모)은 최댓값이 예측 불가능하므로 폭 상한 + 말줄임 + `title` 툴팁을 허용한다. 단 **스캔 대상이 아니라 개별 확인용인 컬럼에 한한다.**
- 값이 0건이라 실측 최댓값이 없는 컬럼은 헤더 폭을 하한으로 삼는다.

### 7-3. sticky

- 가로 스크롤이 발생하는 표는 좌측 식별자 컬럼(LOT번호 등)을 `sticky left-0`으로 고정한다.
- sticky 셀은 **불투명 배경이 필요하다.** 행 hover 배경색이 해당 칸에도 적용되는지 확인할 것.

### 7-4. 입력 그리드

- 값이 `<input>`인 표에는 **`table-fixed`가 필수다.**
  auto-layout이면 타이핑 중 자릿수가 늘어날 때마다 컬럼이 넓어져 옆 칸이 밀리고, 이는 오입력을 부른다.

### 7-5. 숫자 표기 (수량·중량·금액·단가)

- `font-variant-numeric: tabular-nums` 고정폭
- 우측 정렬 / 천 단위 쉼표
- **단위는 값 뒤에 붙인다** (예: `12,165,160원`, `1,000박스`)
  **단위를 컬럼 헤더로 분리하지 않는다** — 품목별 단위가 상이해 헤더 고정이 불가능하다.
- 포맷팅은 공통 함수를 통해서만 한다. 화면별 중복 구현 금지.
  **단일 출처는 `lib/number-format.ts`의 `formatNum(value, unit | {unit, decimals, maxDecimals, empty})`.**
  화면마다 `won()`·`kg()` 같은 로컬 헬퍼를 만들지 않는다.
- **0과 빈 값을 구분한다**: 값이 0이면 `0`, 데이터 없음이면 `—`

### 7-6. 정렬 방향 (표·목록 화면)

- **계산·비교되는 수** (수량, 금액, 중량) → 우측
- **식별자·라벨** (LOT번호, 규격, 미수, 품목, 거래처) → 좌측
- **중앙 정렬은 쓰지 않는다. 예외는 상태 배지뿐이다.**
  입력칸 헤더도 값과 같은 우측 정렬로 맞춘다 — 숫자 열에서 눈은
  상자 테두리가 아니라 자릿수를 따라간다.

### 7-7. 기타

- zebra row는 `--surface-alt`. 행 높이는 PC 38px 고정.
- 상단 필터바 고정 / 테이블 헤더 sticky
- 행 클릭 시 우측 상세 패널(PC) 또는 전체화면 전환(모바일)

### 7-8. 정렬 헤더

**아이콘은 세 상태 모두 같은 계열을 쓴다.** 계열이 바뀌면 "강조 차이"가 아니라 "다른 기능"으로 읽힌다.

| 상태 | 아이콘 | 색 | 표시 |
|---|---|---|---|
| 정렬 안 됨 | `↑↓` | `--text-faint` | 평소 숨김, hover·포커스 시 노출 |
| 오름차순 | `↑` | `--text` | 항상 |
| 내림차순 | `↓` | `--text` | 항상 |

- 숨김은 `display`가 아니라 `opacity`로 한다. 자리를 유지해야 hover 시 헤더 폭이 흔들리지 않는다.
- 크기는 세 상태 모두 동일. 라벨과 간격 4px.
- **아이콘은 라벨의 정렬 반대편에 붙인다.** 좌측 정렬 컬럼 → 라벨 오른쪽 / 우측 정렬 컬럼 → 라벨 왼쪽.
  숫자 컬럼 헤더의 우측선은 값의 우측선과 일치해야 한다.
- 정렬 가능한 헤더는 `cursor: pointer`로 조작 가능함을 알린다.
- **헤더 내용을 `<button>`으로 감싼다.** `<th onClick>`은 키보드로 조작할 수 없다.
  `<th>`에 `aria-sort`(none/ascending/descending)를 지정한다.

  ### 7-9. 폭이 남는 표

§7-2는 컬럼이 많아 폭이 모자란 경우를 다룬다. 마스터 화면처럼 컬럼이 적은 표는 반대 문제를 겪는다.

**판정 기준**

| 조건 | 처리 |
|---|---|
| 컬럼 폭 합계 ≥ 컨테이너 | 기존 방식(px → % 환산) + 가로 스크롤 |
| 컬럼 폭 합계 < 컨테이너 | 설계 폭 고정 + 맨 끝 여백 흡수용 빈 컬럼(스페이서) |

- **컬럼을 비례 확대하지 않는다.** 설계 폭을 지키고 잉여는 스페이서가 흡수한다.
- **스페이서는 `tableMinWidth()` 계산에 포함하지 않는다.** 배열 항목이 아니라 옵션으로 만들어, 구조적으로 포함될 수 없게 한다.
- **스켈레톤과 실제 표는 반드시 같은 스페이서 설정을 쓴다.** 다르면 로딩이 끝나는 순간 컬럼이 튄다.
- 스페이서 셀은 `aria-hidden`으로 처리하고, 행 hover 배경·구분선이 끊기지 않도록 각 행에도 빈 셀을 둔다.

**카드 최대 폭**
- 컬럼 수가 적은 표는 컨테이너 전체 폭을 쓰지 않는다. 카드에 최대 폭을 둔다.
- **카드 폭은 표와 컨트롤 행(검색·필터) 중 큰 쪽이 정한다.** 컨트롤 행 폭도 설계 대상이다.
- 같은 화면의 제목·액션 버튼·컨트롤 행·표 카드는 **모두 같은 최대 폭에 맞춘다.** 오른쪽 끝이 한 선으로 맞아야 한다.
- 표를 가운데 정렬하지 않는다. 좌측 기준을 유지한다.

## 8. 문구와 용어

### 8-1. 문구 규칙

- 시스템 용어가 아니라 **현장 용어**를 쓴다. "레코드 생성" ✕ → "입고 등록" ○
- 버튼은 실행 결과를 그대로 쓴다. "제출" ✕ → "입고 등록" ○
- **버튼 라벨과 그 결과 상태·토스트는 같은 단어를 쓴다.** 확인 버튼이 "승인"이면 상태는 "승인", 토스트는 "승인되었습니다".
- 오류 메시지는 사과하지 않는다. **무엇이 잘못됐고 어떻게 고치는지**를 쓴다.
- 안내·오류 문구는 **`~하세요` 평서 명령형으로 통일한다.** `~해주세요`, `~해 주세요`, `~예요`, `~입니다`를 섞지 않는다.
- 진행 중 표기는 **`동사 + " 중…"`** 으로 고정한다.
  - 말줄임표는 `…`(U+2026) 한 문자만 쓴다. `...` 금지.
  - `처리중`처럼 붙여 쓰지 않는다.

### 8-2. 용어 사전

개념 1개당 1단어로 고정한다. **사전에 없는 단어를 도입하기 전에 사전에 먼저 등재한다.**

| 개념 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 마리수 | **미수** | 사이즈 |
| 박스당 매입 단가 | **수매가** | 수매단가, 매입가 |
| 사오는 곳 | **매입처** | — |
| 파는 곳 | **판매처** | — |
| 보관하는 곳 | **보관처** | 창고 (자사창고/외부창고 복합어는 허용) |
| 품목 (표 헤더) | **품목** | 품명 |
| 품목 (필드 라벨) | **품목명** | — |
| 찾기 동작 | **검색** | 조회, 조회하기 |
| 건을 올린 사람 | **신청자** | — |
| 기록을 처음 만든 사람 | **작성자** | 등록자, 최초작성자 |
| 마지막으로 고친 사람 | **최종 수정자** | 수정자, 편집자 |
| 역할명 | **작업자** | — |

> **`작업자`는 역할명(WORKER) 전용이다.** 거래 이력에서 "그 건을 올린 사람" 컬럼은 `신청자`로 쓴다.
> 단 **DB 필드명은 그대로 두고 화면 라벨만 바꾼다.** 필드까지 바꾸지 말 것.

> **`신청자`와 `작성자`는 다르다.** `신청자`는 결재를 올린 사람(승인·반려가 뒤따른다).
> `작성자`는 결재 흐름 없는 기록을 만든 사람이다 — 작업 정산처럼 여럿이 공동으로 채우는 화면에서 쓴다.
> 공동 편집 화면은 `작성자`와 `최종 수정자`를 **둘 다** 보여준다. 하나만 두면 "지금 이 값이 누구 손을 거쳤나"를 알 수 없다.
> 작업 정산의 DB 필드명은 `작업자`(=작성자) / `최종수정자`이며, 화면 라벨만 위 어휘를 쓴다.

### 8-3. 상수 단일 정의

- **Airtable 옵션 값과 코드 문자열은 상수 한 곳에서만 정의한다.** 화면에서 `'승인 완료'` 같은 리터럴을 직접 비교하지 않는다.
- 근거: 공백 한 칸 차이(`'승인완료'` vs `'승인 완료'`)가 조용한 오작동을 만든 사례가 실제로 2건 있었다.

## 9. 품질 체크리스트

### 공통
- [ ] 색상·폰트·간격·radius를 하드코딩하지 않았다 (토큰만 사용)
- [ ] 본문·배지 텍스트 대비 4.5:1 이상
- [ ] 키보드 Tab 이동 시 포커스 링이 보인다
- [ ] `prefers-reduced-motion` 존중
- [ ] 버튼·배지·빈 상태·로딩에 공통 컴포넌트를 썼다
- [ ] 새로 도입한 용어가 §8-2 사전에 있다

### /admin 전용
- [ ] 1280px에서 정상 표시되고, 그 이하는 축소가 아니라 가로 스크롤이다
- [ ] `minWidth`가 colgroup 합계에서 파생된다
- [ ] 숫자 컬럼이 tabular-nums로 정렬된다
- [ ] 셀 줄바꿈이 없어 행 높이가 균일하다

### 모바일 PWA 전용
- [ ] 375px 폭에서 가로스크롤이 생기지 않는다
- [ ] 입력 필드가 16px 이상이다
- [ ] 터치 타겟이 `min-height: 44px`로 보장된다
- [ ] `type="number"`를 쓰지 않았다

## 10. 미결 사항

결정되지 않았거나 아직 구현되지 않은 항목. **여기 있는 것은 체크리스트에 넣지 않는다.**

| 항목 | 상태 |
|---|---|
| **다크모드** | 구현 없음. 현 시점 우선순위 아님. 도입 시 CSS 변수 + `data-theme` 방식으로, 순수 검정·순수 흰색 텍스트는 쓰지 않는다 |
| **작업 정산 상세 표준화** | `table-fixed` 미적용. 입력 상한 자릿수(수매단가·금액)를 먼저 정해야 함 |
| **재고 집계 표준화** | `useEffect`로 DOM을 재는 폭 맞춤 로직이 얽혀 있어 별도 작업 |
| **기존 radius 정리** | 396곳. §0 정책에 따라 일괄 치환하지 않음 |
| **기존 `.5` 간격 정리** | 450곳. 세로 리듬 전반이 바뀌므로 일괄 치환하지 않음 |
| **인라인 검증 오류 확산** | 33개 admin 화면. §6-3 정책에 따라 입력 폼부터 점진 적용 |
| **입고 이력 재발 가능** | 총폭 1480px. 사이드바를 접고 넓은 모니터를 쓰면 컨테이너가 1480을 넘어 비례 확대가 시작된다. 그 시점에 §7-9 스페이서 전환 필요 |
| **인라인 colgroup 통합** | 손익 추이·매입 통계·재고 집계·작업 정산·워크리스트 5곳이 각자 인라인 `<colgroup>`을 쓴다. `TableColGroup`으로 통합 대상 |
| **정렬 헤더 확산** | 2026-07-29 기준 적용 완료 5화면(보관처·제품·작업자·선박·재고 조회). **남은 정렬 화면은 재고 집계 1개** — `pairW` DOM 측정 로직과 충돌하므로 아래 '재고 집계 표준화'와 함께 처리 |
